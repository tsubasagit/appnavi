# AppNavi 機能拡張仕様書（Phase 2: B2B2B ベンダーイネーブルメント）

## 1. プロジェクト概要

### 1.1 背景と目的

現在、AppNaviは中小企業経営者（エンドユーザー）によるNo-Code利用を主軸としています。
次のフェーズでは、**「ITベンダーやエンジニアが、AppNaviを自社の商材（武器）として活用し、継続的な収益（保守・カスタマイズ）を上げられるプラットフォーム」**へと進化させます。

この「B2B2B」戦略を実現するために、エンジニアが技術力を発揮し、作成した機能を資産化・再利用できる**「Vendor Mode（プロ向けインターフェース）」**を実装します。

### 1.2 ターゲットユーザー

**プライマリ**: ITベンダーの開発者、フリーランスエンジニア

**ニーズ**:
- 顧客の細かい要望に応えるために、Reactコードレベルでの修正を行いたい。
- 一度開発した機能（ロジックやコンポーネント）をライブラリ化し、別の案件で使い回したい。
- 本番環境を壊さずに安全に改修を行いたい（保守性の担保）。

## 2. 実装スコープ・機能要件

既存のAppNavi UIに、エンジニア向けのレイヤーを追加します。

### 2.1 ベンダー向けワークスペース (Pro Interface)

エンドユーザー向けのシンプルさを維持しつつ、権限を持つユーザーには高度なメニューを開放します。

**UI変更点**:
- サイドバーに「Plugins（拡張機能）」「Logic（ロジック）」タブを追加。
- ヘッダーに環境切り替え（Dev/Prod）とデプロイボタンを配置。
- プロパティパネルに「Open Code Editor」への動線を追加。

### 2.2 プラグイン/アセット管理システム (The Armory)

ベンダーが自作した機能を「資産」として登録・管理・再利用する仕組みです。

**機能要件**:
- **カスタムコンポーネント登録**: Reactコンポーネントをインポートまたは作成し、パレットに登録する機能。
- **再利用性**: 登録されたプラグインは、サイドバーの「Plugins」タブからドラッグ＆ドロップで配置可能にする。
- **Github連携 (Nice to have)**: Privateリポジトリからのコンポーネント読み込み機能。

### 2.3 コードオーバーライド・ロジック注入機能 (The Workshop)

No-Codeで生成された標準コンポーネントに対し、プロコードで上書き・拡張を行います。

**機能要件**:
- **コンポーネントレベル**: 特定のUIパーツ（例: グラフ）のデータ処理や描画ロジックをコードで記述可能にする。
- **ブラウザ内エディタ**: Monaco Editor等を組み込み、TypeScriptによるシンタックスハイライトと簡易的な補完を提供する。
- **ロジック注入**:
  - props への介入（データ変換など）
  - イベントハンドラ（onClick 等）のカスタム実装
- **外部API連携**: fetch や axios を用いた外部システム（既存基幹システム、kintone等）への接続ロジック記述の許可。

### 2.4 ライフサイクル管理 (No Fear Operation)

安心して保守運用を行うための環境分離機能です。

**機能要件**:
- **環境分離**: Development（開発）と Production（本番）のモード切替スイッチ。
- **データソースの分離**: Devモード時はモックデータ、または検証用DBを参照。Prodモード時は本番データを参照。
- **デプロイフロー**: Dev環境での変更を確定し、Prod環境へ反映する「Deploy Changes」アクションの実装。

## 4. 技術実装方針

### 4.1 アーキテクチャ

- **権限管理**: ユーザーロール（`user` / `vendor` / `admin`）による機能の表示制御
- **コード実行環境**: ブラウザ内での安全なコード実行（Sandbox環境）
- **プラグインシステム**: 動的インポートとコンポーネントレジストリ

### 4.2 データ構造

```typescript
// プラグイン定義
interface Plugin {
  id: string;
  name: string;
  version: string;
  component: React.ComponentType;
  props: Record<string, any>;
  author: string;
  createdAt: string;
}

// コードオーバーライド
interface CodeOverride {
  componentId: string;
  overrideType: 'props' | 'logic' | 'render';
  code: string;
  environment: 'dev' | 'prod';
}

// 環境設定
interface EnvironmentConfig {
  mode: 'dev' | 'prod';
  dataSource: {
    dev: string;
    prod: string;
  };
}
```

### 4.3 セキュリティ

- **コードサンドボックス**: 実行されるコードを安全に隔離
- **権限チェック**: ベンダーモードへのアクセス制御
- **コード検証**: TypeScript型チェックとリント
