# データ保管とテンプレート設計

## データ保管の設計原則

### 基本方針：「データは個人に、プラットフォームはみんなに」

AppNaviでは、**データの所有権と保管場所を明確に分離**します。

---

## 1. データの分類と保管場所

### ① ユーザーのビジネスデータ（プライベートデータ）

**保管場所**: ユーザーの手元（Google Drive / ローカルストレージ）

**内容**:
- Excelファイル
- Googleスプレッドシート
- CSVファイル
- その他の業務データ

**原則**:
- **AppNaviのサーバーには保存しない**
- 元のファイルは変更されない（読み取り専用）
- ユーザーが完全にコントロールできる
- AppNaviの使用をやめてもデータは残る

**実装方法**:
- Google Sheets API: ユーザーのGoogleアカウントで直接アクセス
- ファイルアップロード: ブラウザのローカルストレージまたは一時的なキャッシュのみ
- データ同期: リアルタイムでユーザーのデータソースから読み取る

---

### ② アプリの設定データ（メタデータ）

**保管場所**: Firebase Firestore（ユーザーごとに分離）

**内容**:
- アプリの基本情報（`App`型）
  - アプリID、名前、説明
  - 選択したテンプレートID
  - ステータス（published/draft/building）
  - ビルド進捗状況
- 方針データ（`PolicyData`型）
  - アプリ名、概要
  - 現状の課題（Before）
  - 解決策（After）
  - 成果指標（KPI）
- UI設定（`UIConfig`型）
  - レイアウトタイプ（list/card/calendar等）
  - テーマカラー
  - 表示する列の設定
- デザイン設定（`DesignConfig`型）
  - ページ構成（`PageConfig`）
  - コンポーネントの配置
  - テーマ設定（色、角丸等）
- データソースの接続情報（`DataSource`型）
  - データソース名
  - タイプ（google-sheets/excel/csv）
  - URL、ファイル名、シートID（参照情報のみ、データ本体は保存しない）

**セキュリティ**:
- Firestoreのセキュリティルールで、ユーザーは自分のデータのみアクセス可能
- データソースのURLやIDは暗号化して保存（オプション）

---

### ③ テンプレートデータ（パブリックデータ）

**保管場所**: Firebase Firestore（パブリックコレクション）またはGitHubリポジトリ

**内容**:
- テンプレート定義
  - テンプレートID
  - 名前、説明、カテゴリ
  - アイコン、色
  - プレビュー情報
- テンプレートのデフォルト設定
  - 推奨されるデータ構造（スキーマ例）
  - デフォルトのUI構成
  - デフォルトのグラフ設定

**原則**:
- すべてのユーザーが共有できる
- 個人情報を含まない
- オープンソースとして公開可能

---

## 2. カスタマイズの内容

### Step 1: テンプレート（方針）のカスタマイズ

**必須項目**:
- テンプレート選択（15種類以上から選択、またはカスタム）
- アプリの基本情報（アプリ名、概要）

**カスタムテンプレート選択時のみ**:
- 現状の課題（Before）
- 解決策（After）
- 成果指標（KPI・目標）

**保存場所**: Firebase Firestore（`PolicyData`型として保存）

---

### Step 2: デザインのカスタマイズ

**カスタマイズ可能な項目**:

1. **ページ構成**
   - ページの追加・削除・編集
   - ページ名、パス、テンプレートタイプ

2. **コンポーネントの配置**
   - 見出し（heading）
   - KPIグリッド（kpi_grid）
   - テーブル（table）
   - グラフ（chart）
   - その他（grid, search, form, kanban, calendar, list, card, stats, action_bar）

3. **コンポーネントのプロパティ**
   - テキスト内容
   - 配置（左/中央/右）
   - データソースの紐付け
   - 表示/非表示の切り替え

4. **テーマ設定**
   - カラーモード（light/dark）
   - プライマリカラー
   - 角丸の設定（none/sm/md/lg/xl/full）

**保存場所**: Firebase Firestore（`DesignConfig`型として保存）

---

### Step 3: データソースの選択

**カスタマイズ可能な項目**:
- データソースの追加・削除
- データソース名
- 接続タイプ（Google Sheets / Excel / CSV）
- 接続情報（URL、ファイル名、シートID）

**保存場所**: Firebase Firestore（`DataSource`型として保存）
**注意**: データ本体は保存せず、参照情報のみを保存

---

### Step 4: グラフ・分析のカスタマイズ

**カスタマイズ可能な項目**:
- グラフタイプの選択（棒グラフ、折れ線グラフ、円グラフ等）
- データソースの紐付け
- 表示項目の選択
- KPIの設定

**保存場所**: Firebase Firestore（`DesignConfig`の一部として保存）

---

## 3. テンプレートの範囲設計

### テンプレートに含めるべき内容

#### ✅ 必須項目（すべてのテンプレートに含める）

1. **方針（Policy）のデフォルト値**
   - テンプレート名
   - 説明文
   - カテゴリ
   - 推奨される用途の説明

2. **デザインのデフォルト構成**
   - 推奨されるページ構成
   - デフォルトのコンポーネント配置
   - テーマカラー（テンプレートごとに異なる）
   - レイアウトタイプ（list/card/calendar等）

3. **データ構造の推奨スキーマ**
   - 推奨される列名
   - データ型の例
   - サンプルデータ構造の説明

#### ⚠️ オプション項目（テンプレートによって異なる）

1. **ビジネスロジックのヒント**
   - 在庫管理: 入出荷の計算方法
   - CRM: 商談ステージの遷移ルール
   - 日報: 承認フローの例
   - **注意**: これは「ヒント」であり、テンプレートに強制されるものではない

2. **グラフのデフォルト設定**
   - 推奨されるグラフタイプ
   - 表示すべき指標の例

3. **サンプルデータ**
   - デモ用のサンプルデータ（オプション）
   - ユーザーの実際のデータに置き換え可能

---

### テンプレートに含めないべき内容

#### ❌ 含めない項目

1. **ユーザーの実際のデータ**
   - テンプレートには個人情報や実際の業務データを含めない
   - サンプルデータのみ（オプション）

2. **固定されたビジネスロジック**
   - テンプレートは「推奨」であり、「強制」ではない
   - ユーザーが自由にカスタマイズできる

3. **複雑なワークフロー**
   - 承認フロー、通知設定などは、テンプレートではなく、アプリの機能として実装
   - テンプレートは「見た目と構造」に焦点を当てる

---

## 4. テンプレートの階層構造

### レベル1: テンプレートID（最小限）

**内容**:
- テンプレートID（例: `crm`, `inventory`）
- 名前、説明、カテゴリ
- アイコン、色

**用途**: テンプレート選択時の表示

**保存場所**: コード内（`PolicyTab.tsx`）またはFirestoreのパブリックコレクション

---

### レベル2: デフォルト設定（推奨）

**内容**:
- デフォルトのUI構成（`PageConfig`）
- デフォルトのテーマ設定（`ThemeConfig`）
- 推奨されるデータ構造（スキーマ例）

**用途**: テンプレート選択時に、デフォルトの設定を自動適用

**保存場所**: Firestoreのパブリックコレクション（`templates/{templateId}/defaultConfig`）

**実装方法**:
```typescript
// テンプレート選択時
const applyTemplateDefaults = (templateId: string) => {
  const defaultConfig = await getTemplateDefaults(templateId)
  // デフォルト設定を適用（ユーザーは後で変更可能）
  updateApp(appId, {
    uiConfig: defaultConfig.uiConfig,
    designConfig: defaultConfig.designConfig
  })
}
```

---

### レベル3: 完全なテンプレート（将来の拡張）

**内容**:
- サンプルデータ
- 完全なページ構成
- ビジネスロジックのヒント

**用途**: より高度なテンプレート機能（将来実装）

**保存場所**: FirestoreまたはGitHubリポジトリ

---

## 5. 推奨される実装方針

### フェーズ1（現在）: 最小限のテンプレート

- テンプレートID、名前、説明のみ
- デフォルト設定はコード内で定義
- ユーザーが手動でカスタマイズ

### フェーズ2（次期）: デフォルト設定の自動適用

- テンプレート選択時に、デフォルトのUI構成を自動適用
- Firestoreにテンプレートのデフォルト設定を保存
- ユーザーは後で自由に変更可能

### フェーズ3（将来）: テンプレートマーケットプレイス

- ユーザーが作成したテンプレートを共有
- コミュニティがテンプレートを改良
- オープンソースとして公開

## 6. データの保存フロー

### アプリ作成時

1. **テンプレート選択**
   - テンプレートIDを`App.template`に保存
   - Firestore: `users/{userId}/apps/{appId}`

2. **方針設定（カスタムテンプレート時）**
   - `PolicyData`を保存
   - Firestore: `users/{userId}/apps/{appId}/policy`

3. **デザイン設定**
   - `DesignConfig`を保存
   - Firestore: `users/{userId}/apps/{appId}/design`

4. **データソース接続**
   - `DataSource`の参照情報を保存
   - Firestore: `users/{userId}/apps/{appId}/dataSources`
   - **データ本体は保存しない**

### データアクセス時

1. **データソースの参照情報を取得**
   - Firestoreから`DataSource`を読み取り

2. **ユーザーのデータソースに直接アクセス**
   - Google Sheets API: ユーザーのGoogleアカウントで認証
   - ファイルアップロード: ブラウザから直接読み取り

3. **データを一時的にキャッシュ（オプション）**
   - パフォーマンス向上のため、一時的にキャッシュ
   - ユーザーのデータはFirestoreに保存しない

---

## 7. セキュリティとプライバシー

### データの分離

- **ユーザーのビジネスデータ**: ユーザーの手元のみ
- **アプリの設定データ**: Firestore（ユーザーごとに分離）
- **テンプレートデータ**: Firestore（パブリック、個人情報なし）

### アクセス制御

- Firestoreのセキュリティルールで、ユーザーは自分のデータのみアクセス可能
- Google Sheets API: ユーザーの明示的な許可が必要
- データソースのURLやIDは、暗号化して保存（オプション）

---

## まとめ

### データ保管の原則

1. **ユーザーのビジネスデータ**: ユーザーの手元（Google Drive / ローカル）
2. **アプリの設定データ**: Firebase Firestore（ユーザーごとに分離）
3. **テンプレートデータ**: Firebase Firestore（パブリック）

### テンプレートの範囲

- **必須**: 方針のデフォルト値、デザインのデフォルト構成、データ構造の推奨スキーマ
- **オプション**: ビジネスロジックのヒント、グラフのデフォルト設定、サンプルデータ
- **含めない**: ユーザーの実際のデータ、固定されたビジネスロジック、複雑なワークフロー

### カスタマイズの自由度

- テンプレートは「推奨」であり、「強制」ではない
- ユーザーはすべての設定を自由に変更可能
- データは常にユーザーの手元に残る
